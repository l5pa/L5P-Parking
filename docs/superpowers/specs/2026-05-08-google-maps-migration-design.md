# Google Maps Migration — Design Spec

**Date:** 2026-05-08
**Issue:** [#2 — Switch to Google Maps API for map tiles](https://github.com/naoyawada/L5P-Parking/issues/2)
**Status:** Approved, ready for implementation plan

## Goal

Migrate from Leaflet + CartoDB Voyager tiles to the Google Maps JavaScript SDK, behind a feature flag, without disrupting the live Leaflet site. Preserve all current behavior:

- Custom black/yellow "P" markers for parking lots
- Selection sync between map markers and list cards
- Auto-fit bounds to show all markers on load
- Mobile-friendly gestures (pinch zoom, pan; cooperative scroll)
- User geolocation marker (blue dot)
- Zero build step; static files served directly from GitHub Pages

## Non-Goals

- Search / Places autocomplete
- Directions or routing
- Street View integration
- Marker clustering (only ~10 lots; unnecessary)
- Caching Google's tiles in the service worker (prohibited by Google's terms)

## Approach: Side-by-Side Engines + URL Flag

Two map engines coexist in the repo. The active engine is chosen at runtime so the live site is never broken during development:

- `src/map.js` — existing Leaflet implementation (default)
- `src/map-google.js` — new Google Maps implementation
- `?engine=google` URL param (or `localStorage.mapEngine = 'google'` for sticky testing) opts into Google Maps
- Both files implement the same `POIMap` public API so `src/app.js` is unaffected

Cutover (after the API key is live and Google version is verified) is a single-line default change in `engine-loader.js`, followed by a cleanup PR removing Leaflet.

## API Key Handling

Google Maps API keys are designed to be public in client-side code, secured via:

- **HTTP referrer restriction:** `naoyawada.github.io/*` and `localhost:*`
- **API restriction:** Maps JavaScript API only

To keep the key out of the public repo (cleaner rotation, separate dev/prod keys), the project will adopt a deploy-time injection model:

- `config.example.js` — committed; documents the shape of `window.APP_CONFIG`
- `config.local.js` — gitignored; local dev copy with a real key
- `config.js` — generated by GitHub Actions at deploy time from repository secrets
- `.gitignore` updated to ignore `config.js` and `config.local.js`

This requires switching the GitHub Pages source from "Deploy from branch (main)" to "GitHub Actions" — a one-time settings change.

## Architecture

```
index.html
├── loads config.js (deploy-injected) — sets window.APP_CONFIG
├── loads src/engine-loader.js — picks engine, injects vendor scripts
└── loads src/map.js OR src/map-google.js (same POIMap interface)
        ↓ used by
       src/app.js (unchanged)
```

## Components

### 1. `config.example.js` (committed)
```js
window.APP_CONFIG = {
  GOOGLE_MAPS_API_KEY: 'YOUR_KEY_HERE',
  GOOGLE_MAPS_ID: 'YOUR_MAP_ID_HERE'
};
```

### 2. `config.local.js` (gitignored)
Developer's local copy of `config.example.js` with a real key for `localhost` testing.

### 3. `.github/workflows/deploy.yml`
On push to `main`:
1. Checks out repo
2. Generates `config.js` from `secrets.GOOGLE_MAPS_API_KEY` and `secrets.GOOGLE_MAPS_ID`
3. Uploads repo (including generated `config.js`) as a Pages artifact
4. Deploys via `actions/deploy-pages`

GitHub Pages source must be set to "GitHub Actions" in repo settings.

### 4. `src/engine-loader.js`
Determines the active map engine:

1. Read `?engine=` from URL; if present, write to `localStorage.mapEngine` for stickiness
2. Read `localStorage.mapEngine`; fall back to default (`'leaflet'`)
3. Inject the appropriate vendor assets:
   - **Leaflet:** `<link>` + `<script>` to unpkg, then load `src/map.js`
   - **Google:** Use Google's recommended dynamic loader (`importLibrary`) bootstrap snippet with `key` and `v: 'weekly'`; then load `src/map-google.js`
4. After engine assets load, dispatch a `mapEngineReady` event so `app.js` can instantiate `POIMap`

### 5. `src/map-google.js`
New file implementing the same public API as `src/map.js`:

| Method | Behavior |
|---|---|
| `constructor()` | Creates `google.maps.Map` on `#map` with `mapId` from config, `gestureHandling: 'cooperative'` on mobile and `'auto'` on desktop, default zoom/center matching current Leaflet code |
| `updateUserLocation(lat, lng)` | Creates/updates an `AdvancedMarkerElement` styled as a blue dot (matches current `.user-location-marker`); centers map |
| `addPOIMarkers(pois)` | One `AdvancedMarkerElement` per POI; HTML content is a styled `<div>` matching current `.poi-marker`; click handler fires the existing `poiMapClick` CustomEvent and calls `selectPOI` |
| `fitToAllMarkers()` | Builds `LatLngBounds`, calls `map.fitBounds` with padding equivalent to current `[30, 30]` and `maxZoom: 17` |
| `selectPOI(poiId)` | Swaps the selected marker's content `<div>` to the selected style (yellow bg, dark P, pulse animation); pans to it |
| `fitBounds(userLat, userLng, pois, maxDistanceMiles)` | Same filter logic; uses `LatLngBounds` and `map.fitBounds` |
| `deselectAll()` | Resets all markers to default content; clears `.active` class on cards |
| `clearPOIMarkers()`, `getCenter()`, `getBounds()` | Direct ports |

### 6. Marker CSS
Extract the marker styles currently injected from `map.js` into `src/styles.css` so both engines reuse the same CSS classes. The `addMarkerStyles()` method gets removed from the Leaflet implementation (or kept as a no-op fallback).

### 7. Map ID setup (one-time, in Google Cloud Console)
Once the API key exists:
1. Map Management → Create Map → type "JavaScript"
2. Apply a clean style: tone down unrelated POI/business labels, keep roads and landmarks legible
3. Save; copy the Map ID into the `GOOGLE_MAPS_ID` secret

## What Stays the Same

- `src/app.js` — only change is waiting for `mapEngineReady` before instantiating `POIMap`; consumes the same `POIMap` interface afterward
- `src/data.js`, `src/utils.js` — untouched
- `src/styles.css` — additive only (marker classes moved in)
- `sw.js` — exclude `maps.googleapis.com` from caching (Google ToS); otherwise unchanged
- All card rendering, geolocation, search, share-from-list behavior

## Cutover Plan

After Google version is verified working via `?engine=google`:

1. Change default in `engine-loader.js` from `'leaflet'` to `'google'`
2. Test default flow on staging / preview
3. Follow-up cleanup PR: remove `src/map.js`, remove Leaflet `<script>`/`<link>` injection paths from `engine-loader.js`, remove Leaflet from README, update CLAUDE.md

## Testing Approach

Manual side-by-side comparison via the `?engine=google` flag once deployed:

- Marker positions match Leaflet version exactly
- Click marker → card highlights and vice versa
- Click empty map → deselect both
- Auto-fit-to-all on load shows all markers with similar padding
- Geolocation centers map and shows blue dot
- Mobile pinch-zoom works; page scroll passes through when not gesturing on map (`cooperative` mode)
- "Find My Location" button works
- Service worker doesn't cache Google tiles

## Open Risks

- **Google Pages deploy switch:** changing Pages source from branch to Actions briefly takes the live site offline (typically <1 min). Plan to do this when traffic is low.
- **Map ID rendering differences:** the cloud-styled map may need iteration to match the visual cleanliness of CartoDB Voyager. Iteration happens entirely in the Cloud Console with no code changes.
- **AdvancedMarkerElement requires `mapId`:** if the Map ID isn't set, advanced markers silently fall back / fail. The loader will hard-fail with a clear console error if `GOOGLE_MAPS_ID` is missing.
